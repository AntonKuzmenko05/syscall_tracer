# Syscall Profiler

Інструмент для профайлінгу системних викликів Linux програм з високоточним вимірюванням часу виконання.

## Опис

Syscall Profiler використовує системний виклик `ptrace` для відстеження всіх системних викликів, які виконує цільова програма. Для кожного syscall вимірюється час виконання з наносекундною точністю за допомогою `clock_gettime(CLOCK_MONOTONIC)`.

## Можливості

- ✅ Відстеження всіх системних викликів через ptrace
- ✅ Високоточне вимірювання часу (наносекунди)
- ✅ Підтримка багатопроцесних програм (fork/vfork/clone)
- ✅ Автоматичне завантаження назв syscalls через `ausyscall`
- ✅ Резервна вбудована таблиця системних викликів
- ✅ Детальний звіт зі статистикою

## Компіляція

```bash
gcc -o syscall_profiler syscall_profiler.c -O2
```

## Використання

### Базове використання

```bash
./syscall_profiler <програма> [аргументи...]
```

### Приклади

```bash
# Профайлінг простої команди
./syscall_profiler ls -la

# Профайлінг програми з аргументами
./syscall_profiler cat /etc/passwd

# Профайлінг власної програми
./syscall_profiler ./my_program arg1 arg2

# Профайлінг багатопроцесної програми
./syscall_profiler firefox
```

## Права доступу

### Варіант 1: Використання sudo
```bash
sudo ./syscall_profiler ls -la
```

### Варіант 2: Встановлення capability (рекомендовано)
```bash
sudo setcap cap_sys_ptrace=eip ./syscall_profiler
./syscall_profiler ls -la  # Тепер працює без sudo
```

### Варіант 3: Без додаткових прав
Для трасування тільки власних процесів sudo не потрібен:
```bash
./syscall_profiler ./my_own_program
```


### Основні компоненти

1. **ptrace механізм** - Перехоплення входу/виходу з syscalls
2. **Вимірювання часу** - `clock_gettime(CLOCK_MONOTONIC)`
3. **Хеш-таблиця** - O(1) пошук статистики за номером syscall
4. **Підтримка багатопроцесності** - `PTRACE_O_TRACEFORK/VFORK/CLONE`

## Обмеження

- **Тільки x86_64:** Поточна версія підтримує лише архітектуру x86_64
- **Wall-clock time:** Вимірюється загальний час, включно з очікуванням I/O
- **Максимум 512 syscalls:** За замовчуванням (можна збільшити `MAX_SYSCALLS`)
- **Накладні витрати:** ptrace додає ~500-1000 нс на кожен syscall

## Технічні деталі

### Як працює вимірювання часу

```c
// Вхід в syscall
current_syscall = regs.orig_rax;
start_time = get_time_ns();

// Виконання syscall в ядрі...

// Вихід з syscall
end_time = get_time_ns();
duration = end_time - start_time;
```

### Підтримка багатопроцесності

Програма автоматично відстежує:
- `fork()` - створення нового процесу
- `vfork()` - оптимізований fork
- `clone()` - створення потоків

Всі дочірні процеси трасуються автоматично, статистика об'єднується.

## Troubleshooting

### "Operation not permitted" при запуску
**Причина:** Недостатньо прав для ptrace

**Рішення:**
```bash
# Або використати sudo
sudo ./syscall_profiler ls

# Або встановити capability
sudo setcap cap_sys_ptrace=eip ./syscall_profiler
```

### "ausyscall: command not found"
**Причина:** Пакет auditd не встановлено

**Рішення:** Програма автоматично використає вбудовану таблицю. Попередження можна ігнорувати.

### Невідомі syscalls у звіті (syscall_XXX)
**Причина:** Syscall не знайдено в таблиці (новий або рідкісний)

**Рішення:** Нормальна поведінка. Номер syscall показується як `syscall_XXX`.
